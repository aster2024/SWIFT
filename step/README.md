# Step-level SWIFT on ProcessBench

This directory applies the SWIFT head to **step-level first-error identification**.
A frozen LLM reads a problem and a step-by-step solution; a SWIFT gated linear head on its hidden states scores each
step, and the first step whose score falls below a threshold is predicted as the earliest error.

Unlike the original SWIFT setting, the solutions here are not generated by the model whose hidden states are read:
ProcessBench solutions were written by twelve Qwen2/2.5 and Llama-3/3.1 models and then reformatted into paragraphs, and
the PRM800K training solutions were written by GPT-4. The frozen LLM therefore acts as a reader of other models' solutions,
and the probe is a lightweight step verifier built on its representations rather than a self-evaluation signal.

- Base model: [Qwen/Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B), frozen; features are the last 4 hidden states (indices 33–36) concatenated per token.
- Head: SWIFT's fused `Linear(feature_dim, 2)` (gate and reward per token), aggregated as a gated mean inside each step's token span; 32,770 trainable parameters.
- Training data: [PRM800K](https://github.com/openai/prm800k) phase 1 + phase 2 training splits, with every problem that also appears in ProcessBench removed.
- Evaluation: [ProcessBench](https://huggingface.co/datasets/Qwen/ProcessBench) (3,400 solutions in four subsets), official metric.
- Released baseline checkpoint (seed 42): [Aster2024/swift-step-probe-qwen3-8b](https://huggingface.co/Aster2024/swift-step-probe-qwen3-8b).

## Files

| File | Purpose |
|---|---|
| `prepare_prm800k.py` | PRM800K → step labels; ProcessBench de-duplication; dev split |
| `step_features.py` | Chat-template rendering and step → token-span mapping via offset mapping (model-agnostic) |
| `train_step_probe.py` | Trains the probe with features computed on the fly; picks the threshold on the dev split |
| `eval_processbench.py` | ProcessBench evaluation (official F1, plus threshold-free step AUC as a diagnostic) |

## Usage

```bash
# 1. data
python step/prepare_prm800k.py <prm800k_dir> <processbench_dir> data/step
# 2. train (about 1 h 45 min for one epoch on one GPU; peak memory about 30 GB)
python step/train_step_probe.py Qwen/Qwen3-8B data/step runs/last4_seed42 --layers last4 --seed 42
# 3. evaluate
python step/eval_processbench.py Qwen/Qwen3-8B runs/last4_seed42 <processbench_dir> runs/last4_seed42/processbench.json
```

## Results (threshold chosen on the PRM800K dev split, not on ProcessBench)

| Probe | Seed | GSM8K | MATH | OlympiadBench | Omni-MATH | Avg. F1 | Step AUC |
|---|---|---|---|---|---|---|---|
| last 4 layers | 42 | 36.8 | 31.5 | 23.9 | 23.6 | 28.9 | 0.776 |
| last 4 layers | 43 | 34.7 | 32.1 | 22.9 | 21.2 | 27.7 | 0.777 |
| last 4 layers | 44 | 39.8 | 28.4 | 18.6 | 17.3 | 26.0 | 0.753 |

Mean over seeds: **27.6** (s.d. 1.5). For reference, ProcessBench reports 36.4 for Skywork-PRM-1.5B, 42.1 for Skywork-PRM-7B,
and 56.5 for Qwen2.5-Math-7B-PRM800K, a 7B model fully fine-tuned on the same PRM800K data.

Notes:
- Using all 37 hidden states (`--layers all`) is unstable across seeds on ProcessBench (30.0 / 11.0 / 4.8) although dev F1 stays at 65–71.
  The step AUC of these probes remains 0.75–0.80: the failure is a global shift of the step scores between PRM800K (GPT-4 solutions)
  and ProcessBench (Qwen and Llama solutions), mostly contributed by early and middle layers, which a fixed threshold cannot absorb.
- A single smoke test (all 37 layers, only the first 300 training samples) reached 27.2 average F1; since all-layer probes are unstable, this is only a hint that data volume may not be the main bottleneck.
- Item-level bootstrap (2,000 resamples within subsets) gives a 95% interval of about ±1.9 points on the average F1 of a single probe.
